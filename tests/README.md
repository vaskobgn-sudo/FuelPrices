# Тестове на „Механата“

```bash
npm i -D playwright          # ако липсва глобално
node tests/run.mjs           # всички набори + балансова симулация
node tests/run.mjs regression
node tools/balance.js        # само кривата на прогресията
```

Излиза с код 1 при поне един провал, за да върши работа в CI.

## Срещу друг билд

`MEHANATA_URL` подменя адреса на играта — за стара версия или за
`site/index.html`, сервиран през http:

```bash
git show v0.1-alpha:mehanata.html > /tmp/v01.html
MEHANATA_URL=file:///tmp/v01.html node tests/run.mjs regression
```

## Защо тестовете изглеждат така

Три неща в харнеса са нарочни и лесно се развалят при пренаписване:

1. **Записът се инжектира през `addInitScript`, не с `localStorage.setItem` +
   `reload()`.** Презареждането пуска `pagehide`, играта записва отгоре и
   инжектираното състояние изчезва, преди новият документ да го е прочел.

2. **Тапва се с ръчно пуснати събития (`tap()` в `lib.mjs`), не с
   `locator.tap()`.** Playwright отказва да тапне елемент с непрекъсната
   анимация — иконата на събитието се върти вечно и чака до timeout.

3. **Парите се четат от записа, не от `#money`.** Показаното е закръглено
   („4.21 млн. лв.“) и не става за сметки. Където се мери за време, преди
   четенето нарочно се пуска скриване на страницата, защото то предизвиква
   запис — автозаписът на 5 секунди не се вмества в прозореца на теста.

## Проверката за двойно начисляване

`времева база → приходът за периода се плаща веднъж` пази най-неприятния бъг,
намиран досега: rAF и `visibilitychange` плащаха едно и също време два пъти.
Проверката е мутационно тествана — при върнат стар код дава 847 вместо 436.
Ако някой пренапише времевата база, това е тестът, който ще падне.
